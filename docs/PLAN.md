## 0. 愿景与设计哲学（保留自 v0.1，经受住拷打）

### 0.1 Manifesto

最好的助手是一个人。而"人"之所以为人，绝大部分不在于其推理与计算的**原生机能**（这部分可被更强的大脑替代），而在于其**一生的经历与记忆**——记忆是自我的载体。

当前各厂商 Agent 把记忆锁在封闭体内、随会话挥发，等于让"人"每次重生都失忆。本项目的出发点：把"记忆"从 Agent 体内**抽离出来**，成为用户拥有、可跨"机体"（跨 Agent）移植的自我载体。不是 Agent 拥有你的记忆，而是**你的记忆调用、驾驭各个 Agent**。

v0.2 补一条站位：完整便携的个人记录同时也是监控者的梦想（雇主或保险公司索要你的记忆包）。用户主权因此包含**选择不透露的权利**——导出可分级、可脱敏、可加密。本项目对抗的不是某家厂商，而是一切对认知连续性的占有。

### 0.2 仿生记忆模型（保留）

| 人类记忆机制 | 系统对应 | 设计含义 |
| --- | --- | --- |
| 意识 / 工作记忆 | Agent 的上下文窗口 | 短期、易失、仅存于"当下思考" |
| 编码门控（重复 / 主观重要性） | 写入纪律 + 重要性评分 | 交互时决定"这条值不值得留" |
| 睡眠中的巩固（短期→长期） | **管家异步后台作业** | 离线发生，不在交互关键路径 |
| 突触重塑 / LTP | 存储层的合并 / 更新 | 记忆被真正"改写"的动作 |
| 海马体（快速情景缓冲） | 情景层（原始语料暂存） | 先快速接住，再慢慢转长期 |
| 新皮层（慢速语义存储） | 语义层（蒸馏后知识） | 巩固后的稳定知识 |
| 遗忘（衰减 / 干扰） | 逻辑遗忘字段 + （v0.2 起）分型衰减 | 不重要的自然淡出 |
| 脑干 / 自主封装 | MCP 服务层包住管家 | 对外不可见，接口稳定 |

不可照搬生物的两处（保留）：
- 生物 24h 持续巩固；管家是计费 LLM 作业，只能**事件 / 定时触发**。
- 生物不可审计；本系统**必须保留审计日志并提供人工覆盖**——这是 Agent 系统应强于生物之处。

### 0.3 铁律：代谢先于积累（v0.2 新增，拷打核心结论）

**积累不等于懂你,策展质量才等于懂你。** 没有代谢的"记录一切"会退化为死文档堆(实证:pi 记忆系统的官方教训--stale 条目反复浮出,导致自信的错误回答)。本项目的主角不是存储,而是代谢。这条铁律决定了仓库身份（§1）与架构重心（§3）。

### 0.4 哲学锚点：记忆 → 叙事自我 → 延展心智（2026-10-14，Q24）

设计不仅从功能出发，也从一个论点出发：

1. **基座模型有世界知识，没有个人经历**——像语义记忆完好、情景记忆缺失的失忆症患者：什么都知道，没有“去年夏天”。Mnevo 补的正是情景层（§0.2 的仿生表在说同一件事）。
2. **自我是被记住、被重构出来的**——Locke（人格同一性=记忆连续）、Tulving（情景记忆→自传体意识）、Bartlett（记忆=重构，非存档）、Ricoeur（叙事同一性）四条线索同指：持续记录+持续重构 = 功能意义上的“自我”在生长。Mnevo 的管线（记录→蒸馏→身份层提案）正是这个结构。
3. **延展的是“你”，不是它**——Clark & Chalmers 延展心智（Otto 的笔记本）：外置记忆扩展的是使用者的自我。Mnevo 是“你+系统”混合体的外置海马体与第二叙事者；“机器只提案、人工确认”铁律（§4.1）的哲学根据：**叙事的最终署名人必须是你**。
4. **诚实边界**：不说“自由意志/意识的开端”——缺内驱目标（目标由用户注入）、第一人称视角（它是索引器不是经历者）、利害（不承担选择后果）。《Her》的 Samantha 之“升华”恰是反例：真正拥有经历的主体会走向自己的目的，而记忆产品不能有这个倾向。

一句话：自我不是被造出来的，是被记住、被重构出来的；Mnevo 把这个过程外置化，并把署名权留给人。

## 1. 项目定位

### 1.1 是什么

**Mnevo = 活的记忆层（living memory layer）**:管家(巩固/代谢)+ 身份层 + 记忆包(导出/导入)+ 各 Agent 习惯适配,架在**可插拔的成熟存储引擎**之上。

- **自建开源仓库**，Apache-2.0，既是自用工具也是个人作品；
- 存储与检索不自研，引擎永远只经 MCP/REST 调用，**绝不 import 引擎内部**（保证可换底座）；
- 一句话定位:**"会睡觉的文件柜"**--竞品做被动的“文件柜”，Mnevo 做“睡眠”。

### 1.2 不是什么（决策墓碑，防止回潮）

- ❌ 不自创公共记忆标准（社区已有 PAM 等，见 §2；v0.2 仅做格式映射）；
- ❌ 不自研检索内核 / 图引擎 / embedding；
- ❌ 不做多租户 SaaS 与社区运营，第一年它是私人工具，别人爱用不用；
- ❌ v0.1 不做自动衰减（误杀风险高，先观察三个月）；
- ❌ 不做团队/家庭共享脑（schema 留口子，远期再议）。

## 4. 记忆模型与纪律

### 4.1 两层结构（保留）

- **身份层（常驻注入）**：persona（沟通风格/背景）、values & principles（价值观/决策偏好）、goals（目标）、active threads（活跃上下文：进行中的项目与未闭环事项）。形态 = **markdown 文件 + git 版本化**（pi 的 MEMORY.md 模式已验证手工策展可行）。**管家对身份层只有提案权，人工确认后生效**——"你是谁"不许机器自作主张。
- **知识层（按需召回）**：事实与经历，`recall` 触达。

### 4.2 记录哲学：一切经历皆可记，载荷永不入脑

- 工作是人生的一部分，接入的事都记——**可以慢慢忘，不能转头就忘**（用户核心立场）。
- **经历 / 载荷分界**（铁律）：大脑记录"做了什么、学到什么、卡在哪、东西在哪"（经历、教训、指针）；**公司数据本体（财务文件内容、数字、客户信息）永不作为记忆内容入库**。类比：员工记得工作经历，但不会把客户数据库背回家。

### 4.3 原始语料与遗忘

- **原始语料（transcripts/情景）加密长期留存**（不用 TTL 物理删除）；
- **逻辑遗忘 = 字段控制**：被标记的条目同时从**召回**与**蒸馏**两条管道排除——像人一样，痕迹还在，但想不起来；
- 保留显式 **hard-delete** 命令作"真的要彻底忘"的出口；
- 代价须知：长期留存原始件 = VPS 被攻破时爆炸半径变大 → 缓解见 §9（加密、OAuth-only、加密备份）。

### 4.4 衰减（v0.2 起，v0.1 暂缓）

v0.1 不做自动衰减。观察三个月后按**分型衰减**引入：身份层永不自动衰减；fact 被 supersede 时失效；skill 靠验证维护；仅 episode 适用遗忘曲线+访问强化。记忆包格式预留 `valid_from/valid_to`、`supersedes` 字段（谱系优先于破坏性合并——"他曾偏好X后改Y"本身是重要记忆）。

## 5. 接口设计

### 5.1 Engram 层对外暴露/要求的工具语义

| 工具 | 作用 |
| --- | --- |
| `get_context(token_budget)` | 返回预装配上下文：身份层 → 活跃线程 → top-k 相关记忆，**确定性排序**（打爆下游 prompt cache 是真实成本） |
| `ingest_session(transcript)` | **被动摄取**：Agent 只负责"倒带子"，抽取/判重/结构化由服务端管家完成 |
| `recall(query, namespace?, top_k)` | 语义 + 元数据过滤召回 |
| `recent(limit, namespace)` | 近期记忆，用户核验"记了什么" |
| `forget(id)` / `hard_delete(id)` | 逻辑遗忘 / 物理删除 |
| `export()` / `import()` | 记忆包往返（验收测试的一部分） |

设计原则（v0.2 新增）：**假设 Agent 是笨的**。智能向服务端下沉——被动摄取、预装配上下文，使最笨的 Agent 也能获得完整体验；Adapter 只需教三件事：启动调 `get_context`，结束调 `ingest_session`，别把密钥写进来。

### 5.2 记忆包 v0.1（私有格式，不宣称标准）

- 内容：记忆 + 身份层 + manifest + **版本号**（格式演进的生命线）；
- v0.2 增加 PAM v1.0 映射器（导出兼容社区标准）；
- 备份与"用户拥有"叙事的物理载体（§9）。

## 6. Adapter 设计（习惯说明书）

MCP 封装的是"手"（管道、schema、鉴权），**没封装"习惯"**（何时调什么、写什么、不写什么）。Adapter = 每 Agent 一页 markdown 习惯书 + 连接配置，不是每 Agent 一套代码。注入机制因厂而异（pi=extension/skill；ChatGPT=custom instructions+connector；Claude=项目指令/connector），习惯书本身厂商中立。

最小内容：①服务定位一句话；②三条核心纪律（见 §5.1）；③写入纪律：什么算个人事实、什么算任务垃圾、经历/载荷分界；④默认 namespace 与作用域。

## 7. 管家（Butler）设计

- **多条件触发**（用户定）：时间窗（如夜间）/ 记录数阈值 / 手动唤醒 / 事件驱动，并存可配；
- **职责**：情景→语义蒸馏（提炼而非堆积）、身份层 diff 提案（人工确认）、逻辑遗忘标记执行、审计日志（每一步动作落笔）；
- **LLM 路由**：personal 区 → 便宜云端模型，**单次成本上限 ~¥0.5**；work 区蒸馏冻结已于 2026-10-14 解除（公司确认无限制），与 personal 同路由同成本阀；**经历/载荷分界（§4.2）不变**——政策放行不等于数据搬运明智；
- **工程要求**：操作幂等、journal 化（合并到一半崩溃不得损数据）；后期可两档模型（便宜抽取 / 好模型合并）；
- **人工策展不定期** → 审计日志即常规巡检的替代品；不看日志 = 没有代谢。

## 9. 部署、备份与安全

### 9.0 双宿主拓扑（2026-10-14 起）

- **work 引擎**：公司开发服务器（ssh 免密已配）。服务只绑 127.0.0.1，经 SSH 隧道供 pi 使用；WorkBuddy 接入时再评估 HTTPS+OAuth 暴露方案（§14-6）。合规姿态：工作数据留在公司基础设施内，蒸馏调用外部 LLM 已获公司“无限制”许可（Q20）。
- **personal 引擎**：自有 VPS（或本地），基线见 9.1；work 区验证通过后跟进部署。
- **备份分区**：work 记忆包留在公司基础设施（不外流到个人 GitHub）；personal 记忆包 → age 客户端加密 → 个人 GitHub 私有仓哑存储（9.2）。
- **供应链警讯**：2026-09 MemTensor（MemOS/OpenClaw 记忆工具链）npm/PyPI 包遭投毒（窃密木马 sckit）——记忆类依赖必须 pin 版本 + 校验哈希，升级走隔离环境。

### 9.1 VPS 部署基线（personal 引擎）

- Remote MCP 仅 HTTPS + OAuth 2.1（mcp-memory-service 自带）；不暴露 stdio/裸 HTTP；
- ufw 只开 443；fail2ban；自动安全更新。

### 9.2 备份 = "用户拥有"的物理证据

- 每日自动导出记忆包 → **客户端加密（age）** → **GitHub 私有仓当哑存储**（GitHub 不是加密层，密钥永远在用户手里）；数据量增大后换云厂商对象存储，同加密不改；
- 每月一份全量包存三处（VPS 外两处，含家用机）。

## 10. 合规红线

- **经历/载荷分界**（§4.2）+ **work 区蒸馏冻结**（§7）在公司政策查明前为默认态；
