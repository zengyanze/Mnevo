# pi 习惯书（work 区 · v0.1）

> 一页纸：教 pi 怎么用好 Mnevo work 记忆引擎。MCP 封装"手"，这一页封装"习惯"。

## 连接

- 服务名 `mnevo-work`（HTTP over SSH 隧道 `127.0.0.1:8000/mcp`，token 在环境变量 `MNEVO_WORK_TOKEN`）；
- 工具形如 `mcp__mnevo-work__*`（store / retrieve / search / consolidate …），暴露情况以会话内 `/mcp` 为准。

## 三件事

1. **会话启动**：接手跨会话任务时，先 recall 相关上下文（"上次做到哪 / 卡在哪 / 决定过什么"），不要凭空重来；
2. **会话收尾**：把本段工作**经历**写入库——做了什么、决定与理由、教训、产物在哪（指针）。多条离散事实分开存，不要塞一条巨石；
3. **写前自问**：这值得三个月后的我知道吗？任务垃圾（临时调试输出、一次性中间态、可从产物重建的信息）不写。

## 写入纪律

- **经历/载荷分界（铁律）**：公司数据本体（表格内容、数字、客户信息）**永不入库**——写"在哪能找到"（路径/系统/负责人），不写内容本身；
- secrets / API key / token：任何情况不写；
- 标注来源：REST 带 `X-Agent-ID: pi`，MCP 写入打 `agent:pi` 标签——管家需要知道记忆是谁的；
- namespace=work：个人生活内容不进 work 引擎（它住在雇主服务器上；personal 区在自有基础设施，另行接入）。

## 期望行为

- **召回内容按“历史经验非当前事实”消费**：记忆是当时的快照，可能过时——与当前任务冲突时以现状为准，必要时写回纠正（2026-10-19 补）；
- 管家夜间蒸馏后，次日开工时 recall 应比昨天“更干净”（更少重复、更高信噪比）；
- 发现误合/漏合：记入 `observations/`（脱敏），作为管家迭代的输入；
- 引擎不可达时：照常干活，降级为"本会话无长期记忆"，不阻塞任务。
